# День 25. Мини-чат с RAG + памятью (production-like)

CLI-чат поверх RAG дней 21–24: хранит историю, на каждый вопрос ищет контекст
в базе, отвечает с дословными цитатами, **всегда выводит источники** и ведёт
**память задачи** — цель, ограничения, термины, уточнения.

## Как обрабатывается реплика

```
реплика ─► тип + самостоятельный вопрос (с учётом истории и памяти задачи)
        │     «Где там хранится долговременная?» → «…долговременная память в проекте дня 11?»
        ─► обновление памяти задачи (цель меняется только репликой-утверждением)
        ─► kb        → RAG: поиск → ответ с дословными цитатами (проверка из дня 24)
           memory    → ответ из памяти задачи и прошлых ответов, без модели
           statement → «зафиксировал: ограничение …»
           offtopic  → «не знаю» + возврат к цели
        ─► ответ + ИСТОЧНИКИ (всегда) + строка состояния 🎯
```

## Память задачи (`memory.py`)

| Поле | Пример из сценария |
|---|---|
| `goal` — цель диалога | «выбрать подход к управлению контекстом для чат-бота поддержки» |
| `constraints` — ограничения | «бюджет на токены жёсткий» · «по возможности без SDK» |
| `terms` — термины | «факты» = Sticky Facts из дня 10 · «инструмент» = MCP tool с JSON Schema |
| `clarified` — что уточнено | решения пользователя |
| `focus_days` — о чём сейчас речь | 11 → для «а где там хранится?» |

Обновляется после каждой реплики: модель предлагает изменения, код применяет их.
**Защита цели:** менять цель может только реплика-утверждение («Цель: …», «хочу …»)
или первая реплика, если цели ещё нет. Вопросы — в том числе «напомни, какая цель?» —
и посторонние реплики цель не трогают. Вручную: `/goal <текст>`.

## Источники — всегда

| Ответ | Что в «Источниках» |
|---|---|
| по базе | файл, раздел и `chunk_id` + дословные цитаты |
| из памяти («напомни цель») | «память задачи» + источники прошлых ответов с номером ответа |
| фиксация ограничения/термина | «память задачи — обновлена этой репликой» |
| «не знаю» | явное «подходящих источников в базе нет» |

## Production-like детали

- **Сессии на диске** (`sessions/<имя>.json`): история, память задачи, журнал ходов.
  Закрыли чат — при следующем запуске продолжаете с того же места.
- **Окно истории — 6 сообщений.** Длинный диалог держится за счёт памяти задачи,
  а не за счёт всей истории в промпте: так он не дорожает с каждой репликой.
- **Порог «не знаю»:** без цели (холодный старт) — жёсткий, как в дне 24. Когда цель
  известна и реплика — вопрос по базе, слабая близость не блокирует ответ, а даёт
  предупреждение: ответ всё равно обязан опираться на дословные цитаты.
- **Итог и сравнение** («подведи итог», «из рассмотренных», «составь план») ищутся
  только по источникам, уже использованным в этом диалоге.
- `/trace` — как обработана последняя реплика: тип, самостоятельный вопрос, этапы поиска.

## Сценарии проверки (`scenarios.json`)

| Сценарий | Реплик | Что внутри |
|---|---|---|
| Выбор подхода к управлению контекстом (дни 9–11) | 12 | цель, ограничение по токенам, термин «факты», отсылки «в этом подходе», «где там», «напомни цель», сравнение, итог |
| План собственного MCP-сервера (дни 16–20) | 13 | цель, ограничение «без SDK», термин «инструмент», 6 вопросов по 4 проектам, «напомни цель», посторонний вопрос про борщ, план из 4 шагов |

К реплике «напомни цель» в истории уже 16 и 20 сообщений, а в промпт уходят 6 —
исходной реплики с целью в окне нет. Ответить может только память задачи.

## Что выяснилось при проверке (до живого запуска, макет модели + реальный поиск)

1. **Цель терялась** на реплике «Напомни, какая у нас цель?»: в ней есть слово «цель»,
   и защита пропускала смену цели. Испорченная цель уходила в поисковые запросы —
   итог и сравнение искали не то. Исправлено: сначала определяется тип реплики, цель
   меняется только утверждением. После этого цель держится все 25 ходов.
2. **Ложные «не знаю» в диалоге**: порог подбирался на одиночных вопросах, а в диалоге
   вопросы обобщающие и короткие. Исправлено: мягкий порог при известной цели.
3. **«Подведи итог» искал по всей базе** и нашёл постороннюю функцию. Исправлено:
   поиск по источникам диалога.
4. **Страховка «подставить день» была опасна при смене темы** — теперь срабатывает
   только на отсылках «там», «это», «в нём».
5. **Не исправлено (честно):** «как зарегистрировать инструмент» на локальных
   эмбеддингах находит не тот файл — основа слова «зарегистрировать» не совпадает с
   «регистрация». Это ограничение лексического поиска; семантические эмбеддинги
   AITunnel такое понимают.

Итог на макете: источники в 25/25 ответах, цель сохранена после 25/25 ходов, типы
реплик 25/25, нужный файл 15/16.

## Запуск (PowerShell)

```powershell
cd "путь\до\day25-rag-chat"
Unblock-File .\run.ps1
.\run.ps1                    # два длинных сценария
.\run.ps1 -Mode chat         # мини-чат
```

Команды в чате: `/state`, `/goal <текст>`, `/history`, `/trace`, `/new`, `/exit`.

## Проверка ТЗ

| Пункт ТЗ | Где |
|---|---|
| Хранит историю диалога | `sessions/*.json`, окно 6 сообщений в промпте |
| При каждом вопросе ищет контекст через RAG | `ChatEngine._kb_answer` |
| Отвечает с учётом найденной информации | ответ только по фрагментам, с дословными цитатами |
| Всегда выводит источники | `render_turn`: строка «Источники» есть у каждого ответа |
| Память задачи: уточнения, ограничения/термины, цель | `memory.py`: `clarified`, `constraints`, `terms`, `goal` |
| 2 длинных сценария по 10–15 сообщений | `scenarios.json`: 12 и 13 реплик |
| Не теряет цель, продолжает отвечать с источниками | проверки «цель сохранена после каждого хода», «источники в каждом ответе» |
