# День 10. Управление контекстом: 3 стратегии (без summary)

Формат тот же, что и в `day9-context-compression`: Python-агент, AITunnel,
запуск через PowerShell.

## Быстрый старт (проще всего)

В папке есть `run.ps1` — сам находит рабочий Python, спрашивает ключ (если
он ещё не задан) и запускает нужный режим. Вместо 5-6 отдельных команд:

```powershell
cd "путь\до\day10-context-strategies"
.\run.ps1                 # интерактивный чат
.\run.ps1 -Mode compare   # сравнение всех трёх стратегий
```

Если Windows откажется запускать `.ps1` файл ("выполнение сценариев
отключено в этой системе"), один раз выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Mode compare
```

Дальше в README — ручные команды по шагам, на случай если `run.ps1`
почему-то не подходит и нужно разобраться, что именно идёт не так.

## Файлы

- `run.ps1` — автозапуск в одну команду (см. выше).
- `context_strategies.py` — три независимые стратегии:
  - **`SlidingWindowStrategy`** — хранит только последние `window_size`
    сообщений, всё остальное отбрасывается безвозвратно.
  - **`FactsStrategy`** — отдельный блок `facts` (словарь ключ-значение:
    цель, ограничения, бюджет, решения, договорённости), который
    обновляется LLM-вызовом после каждого сообщения пользователя;
    в запрос уходит `facts + последние window_size сообщений`.
  - **`BranchingStrategy`** — дерево сообщений. Можно поставить
    `checkpoint` в любом месте диалога, создать от него несколько
    независимых веток (`create_branch`) и переключаться между ними
    (`switch`). Каждая ветка «помнит» всё до точки ветвления плюс
    свою собственную независимую историю после неё.
- `chat.py` — интерактивный агент с **переключателем стратегий**
  (`/strategy window|facts|branch`) и полным набором команд для веток.
- `compare.py` — прогоняет один и тот же сценарий сбора ТЗ (сайт
  бронирования антикафе, 9 базовых реплик) через все три стратегии:
  Sliding Window и Facts — линейно на 14 репликах с контрольными
  вопросами на память; Branching — 9 базовых реплик → checkpoint →
  2 независимые ветки («добавить мобильное приложение» /
  «урезать фичи из-за сроков»), в конце каждой — вопрос «что было в
  начале», чтобы проверить, не потерялись ли факты до ветвления.

## Запуск — интерактивный агент

```powershell
cd "путь\до\day10-context-strategies"
$env:AITUNNEL_API_KEY = "sk-aitunnel-xxx"
python .\chat.py
```

Команды внутри чата:

| Команда | Что делает |
|---|---|
| `/strategy window\|facts\|branch` | переключить активную стратегию (история диалога переносится в новую) |
| `/window N` | изменить размер окна (window / facts) |
| `/facts` | показать текущий блок facts |
| `/checkpoint <имя>` | (branch) поставить чекпоинт на текущем месте |
| `/branch <имя> [from <чекпоинт>]` | (branch) создать и переключиться на новую ветку |
| `/switch <имя_ветки>` | (branch) переключиться на существующую ветку |
| `/branches` | (branch) список веток, отмечена активная |
| `/history` | показать сообщения активного контекста |
| `/stats` | реальный расход токенов текущей стратегии с начала сессии |
| `/exit` | выход |

## Запуск — сравнение всех трёх стратегий

```powershell
cd "путь\до\day10-context-strategies"
$env:AITUNNEL_API_KEY = "sk-aitunnel-xxx"
python .\compare.py
```

⚠️ Делает реальные запросы к API на всех трёх стратегиях (14 + 14 + (9+3+3)
= ~46 обращений к основной модели, плюс 14 отдельных вызовов на извлечение
фактов для стратегии Facts). Отредактируйте сценарий в `compare.py`
(`BASE_TURNS`, `LINEAR_CONTINUATION`, `BRANCH_A_TURNS`, `BRANCH_B_TURNS`),
если хотите его короче/длиннее.

После прогона появятся три файла с транскриптами:
- `transcript_window.json`
- `transcript_facts.json` (плюс итоговый накопленный `facts`)
- `transcript_branching.json` (основная ветка + обе дочерние)

## Пример прогона в MOCK-режиме (без ключа, только механика)

| Стратегия | input-токены | output-токены | доп. вызовы (facts) |
|---|---|---|---|
| Sliding Window | 1821 | 350 | — |
| Facts | 1343 | 350 | 14 |
| Branching | 4774 | 375 | — |

Уже на заглушках видно ожидаемую картину: **Facts экономит токены**
сильнее всего (сжимает историю в компактный список фактов), **Sliding
Window** — посередине (совсем не помнит то, что выпало из окна),
**Branching** — самый дорогой по токенам, потому что ничего не
выбрасывает: он не про экономию, а про то, чтобы можно было безопасно
исследовать разные продолжения диалога, не теряя общий контекст.

## Как оценить качество и стабильность (нужен реальный прогон)

1. Запустите `compare.py` с реальным `AITUNNEL_API_KEY`.
2. В `transcript_window.json` и `transcript_facts.json` проверьте ответы
   на контрольные вопросы («напомни стек и бюджет», «что мы решили про
   регистрацию», «какой был дедлайн в начале») — не потерялась ли
   деталь при усечении окна.
3. В `transcript_branching.json` проверьте, что оба ответа на «как это
   меняет бюджет/дедлайн, которые обсуждали в начале» (в конце каждой
   ветки) правильно называют исходные бюджет/дедлайн — это проверка,
   что ветвление не портит память о том, что было до checkpoint.
4. Заполните `RESULTS.md` — там уже есть таблицы под все 4 критерия
   сравнения (качество, стабильность, токены, удобство).
