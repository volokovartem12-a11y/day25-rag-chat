# День 11. Модель памяти агента (memory layers)

Формат тот же, что в `day9` и `day10`: Python-агент, AITunnel, запуск через PowerShell.

## Быстрый старт

```powershell
cd "путь\до\day11-memory-layers"
.\run.ps1              # интерактивный агент
.\run.ps1 -Mode demo   # демонстрация: что попадает в слои и как это влияет на ответы
```

Если Windows заблокирует запуск `.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Mode demo
```

Скрипт сам находит рабочий Python, спрашивает ключ и ставит зависимости.

## Описание модели памяти

| Слой | Что хранит | Время жизни | Где в промпте |
|---|---|---|---|
| **Краткосрочная** (`ShortTermMemory`) | последние N реплик диалога дословно | до вытеснения из окна | в массиве `messages` |
| **Рабочая** (`WorkingMemory`) | слоты текущей задачи: название, собранные параметры, что ещё не заполнено, заметки | пока задача не закрыта | блок `=== РАБОЧАЯ ПАМЯТЬ ===` в system |
| **Долговременная** (`LongTermMemory`) | `profile` (кто пользователь), `decisions` (принятые решения), `knowledge` (факты о проекте) | постоянно, файл `memory_store.json` — переживает перезапуск | блок `=== ДОЛГОВРЕМЕННАЯ ПАМЯТЬ ===` в system |

Ключевое: слои **хранятся отдельно** (разные объекты, разный жизненный цикл,
долговременная — вообще на диске) и **собираются в промпт раздельно**, так что
по команде `/context` видно, какой слой что именно добавил и сколько это стоит
в токенах.

### Как выбирается, что и куда сохраняется

Два явных режима:

**1. Ручной** — вы сами командуете:
```
/task set бюджет=400000              → рабочая
/remember profile роль=продакт       → долговременная / профиль
/remember decision Регистрация не нужна → долговременная / решения
/remember knowledge хостинг=VPS 4GB  → долговременная / знания
```

**2. Авто** (`/auto on`) — LLM-роутер на каждую реплику решает, что и в какой
слой положить, и **обязан вернуть обоснование**. Все его решения пишутся в
журнал и смотрятся командой `/routing`:
```
→ long_profile/имя: Игорь
   причина: устойчивый факт о пользователе, полезен между сессиями
→ working/бюджет: 400000 рублей
   причина: параметр текущей задачи по сбору ТЗ
```
То есть авто-режим не превращает маршрутизацию в чёрный ящик — решение всегда
можно посмотреть и оспорить.

## Файлы

- `memory_layers.py` — три класса слоёв + `MemoryManager` (сборка контекста,
  разбивка токенов по слоям) + LLM-роутер.
- `chat.py` — интерактивный агент со всеми командами памяти.
- `demo.py` — прогоняет один сценарий в трёх режимах и показывает разницу.
- `run.ps1` — запуск в одну команду.
- `memory_store.json` — создаётся при первом запуске, это и есть
  долговременная память на диске (в git не коммитится).

## Команды агента

| Команда | Слой | Что делает |
|---|---|---|
| `/task start <имя> [слот1,слот2]` | рабочая | начать задачу, задать нужные слоты |
| `/task set ключ=значение` | рабочая | записать слот |
| `/task note <текст>` | рабочая | заметка |
| `/task show` | рабочая | показать |
| `/task done` | рабочая → долговременная | закрыть задачу, итог уходит в решения |
| `/remember profile ключ=значение` | долговременная | профиль |
| `/remember decision <текст>` | долговременная | решение |
| `/remember knowledge ключ=значение` | долговременная | знание |
| `/auto on\|off` | — | авто-маршрутизация через LLM |
| `/routing` | — | журнал: что, куда и почему |
| `/memory` | все | что лежит в каждом слое |
| `/context` | все | какой промпт реально уходит в модель + вклад слоёв в токенах |
| `/stats` | все | размеры слоёв, расход токенов |
| `/forget [profile\|decisions\|knowledge\|all]` | долговременная | очистить |
| `/reset` | кратк. + рабочая | новая сессия, долговременная остаётся |
| `/exit` | — | выход |

## Проверка: как слои влияют на ответы

`demo.py` прогоняет один и тот же сценарий (сбор ТЗ, 8 реплик) в трёх режимах:

- **A. Только краткосрочная** (окно 4 реплики) — всё, что вышло за окно, забыто.
- **B. Три слоя, ручная раскладка** — данные разложены по слоям явно.
- **C. Три слоя, авто-роутер** — раскладывает LLM, решения печатаются.

Затем задаются 4 контрольных вопроса про детали из начала диалога
(имя и роль, бюджет и сроки, решение про регистрацию, ограничение по хостингу)
и сравниваются ответы трёх режимов.

Пример прогона в MOCK-режиме (без ключа, только механика — ответы-заглушки):

| Режим | кратк. | раб. | долгов. | input |
|---|---|---|---|---|
| A. Только краткосрочная | 52 | 0 | 0 | 1114 |
| B. Три слоя, ручная раскладка | 53 | 56 | 59 | 2370 |
| C. Три слоя, авто-роутер | 52 | 0 | 0 | 1114 |

Видно главный компромисс: режим B дороже по токенам (~2х), потому что тащит в
каждый запрос блоки рабочей и долговременной памяти — но именно за счёт них он
и способен ответить на вопросы про начало диалога. Режим C в mock-режиме пуст,
так как роутер-заглушка ничего не извлекает — на реальном API он заполнится.

**Чтобы получить настоящие цифры и сравнить качество ответов, нужен прогон с
реальным ключом** — заполните после этого `RESULTS.md`.
