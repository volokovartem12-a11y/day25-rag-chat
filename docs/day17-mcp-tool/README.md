# День 17. Первый инструмент MCP

Свой MCP-сервер вокруг CRM API + агент, который вызывает его инструменты
и использует результат в ответе.

## Архитектура

```
Пользователь ──► agent.py ──(вопрос + список инструментов)──► LLM (AITunnel)
                    │                                            │
                    │◄──────── «вызови search_clients(Анна)» ────┘
                    │
                    ├──(MCP, stdio)──► mcp_server.py ──► crm_api.py (mock CRM)
                    │◄──────────── результат (JSON) ─────────┘
                    │
                    └──(результат инструмента)──► LLM ──► ответ пользователю
```

## Файлы

| Файл | Роль |
|---|---|
| `crm_api.py` | mock CRM — «внешний API»: клиенты и заказы. Работает без сети |
| `mcp_server.py` | **MCP-сервер**: регистрирует 3 инструмента, описывает параметры, возвращает результат |
| `mcp_client.py` | общий код клиента: подключение по stdio, разбор результата, перевод схем в формат LLM |
| `demo_call.py` | прямой вызов инструментов из приложения, **без LLM и без ключа** |
| `agent.py` | **агент**: LLM сама выбирает инструмент, агент вызывает его через MCP |
| `run.ps1` | запуск в одну команду |

## Инструменты сервера

| Инструмент | Параметры | Что возвращает |
|---|---|---|
| `search_clients` | `query` (строка, обязательный) | найденные клиенты с id |
| `get_client_orders` | `client_id` (целое ≥1, обязательный), `status` (new / in_progress / done / cancelled, необязательный) | заказы клиента + сумма без отменённых |
| `create_order` | `client_id`, `item`, `amount` (> 0) — все обязательные | созданный заказ |

Параметры описаны через `Annotated[тип, Field(description=...)]` — SDK сам
собирает из них JSON Schema (`inputSchema`), которую видит клиент и модель.
Ошибки (например, несуществующий клиент) возвращаются клиенту как `isError=True`.

## Запуск (PowerShell)

```powershell
cd "путь\до\day17-mcp-tool"
Unblock-File .\run.ps1

.\run.ps1                                              # 1) прямой вызов, без ключа
.\run.ps1 -Mode agent -Ask "Какие заказы у Анны Смирновой?"   # 2) агент, один вопрос
.\run.ps1 -Mode agent                                  # 3) агент, диалог
```

Если Windows блокирует: `powershell -ExecutionPolicy Bypass -File .\run.ps1`

## Что должно получиться

**Шаг 1 (без ключа)** — список инструментов с параметрами, результат
`search_clients`, затем заказы клиента по id, взятому из первого результата,
и пример ошибки `isError=True` для несуществующего клиента.

**Шаг 2 (агент)** — видно, как агент ходит в MCP:

```
Вы: Какие заказы у Анны Смирновой?
  [MCP →] search_clients({"query": "Анна Смирнова"})
  [MCP ←] {"query": ..., "found": 1, "clients": [{"id": 2, ...}]}
  [MCP →] get_client_orders({"client_id": 2})
  [MCP ←] {"client": ..., "orders": [...], "total_amount_without_cancelled": 4800}
Агент: У Анны Смирновой один заказ — шиномонтаж на 4800 ₽, статус «новый».
```

Точные формулировки зависят от модели, но цепочка вызовов и цифры
из CRM должны быть такими.

## Проверка ТЗ

| Пункт ТЗ | Где |
|---|---|
| Свой MCP-сервер вокруг API | `mcp_server.py` вокруг `crm_api.py` |
| Регистрация инструмента | `@mcp.tool()` в `mcp_server.py` |
| Описание входных параметров | `Annotated[..., Field(description=...)]` → `inputSchema` (виден в шаге 1) |
| Возврат результата | инструменты возвращают dict → JSON клиенту; ошибки — `isError` |
| Подключить инструмент к агенту | `agent.py`: `list_tools` → формат function calling → LLM |
| Вызвать из приложения | `demo_call.py` (напрямую) и `agent.py` (через LLM): `session.call_tool` |
| Получить и использовать результат | id из `search_clients` передаётся в `get_client_orders`; LLM отвечает цифрами из CRM |

## Как заменить mock на настоящий API

Переписать функции в `crm_api.py` на HTTP-запросы к реальному сервису
(Яндекс.Трекер, amoCRM и т.п.). `mcp_server.py` и `agent.py` менять не нужно.
