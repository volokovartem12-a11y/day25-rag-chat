# День 19. Композиция MCP-инструментов

Автоматический пайплайн из трёх MCP-инструментов: первый получает данные,
второй обрабатывает, третий сохраняет результат. Между шагами проверяется,
что данные переданы без потерь и искажений.

## Схема

```
pipeline.py (MCP-клиент)
   │
   ├─[1] search(query) ──────────► статьи из базы знаний + combined_text
   │         │
   │         └── combined_text ──┐
   ├─[2] summarize(text) ◄───────┘ выжимка (локально или через AITunnel)
   │         │
   │         └── отчёт Markdown ─┐
   └─[3] save_to_file(content) ◄─┘ файл в папке output/
```

Все три инструмента живут в одном MCP-сервере (`mcp_server.py`), клиент
запускает его сам и общается по stdio.

## Файлы

| Файл | Роль |
|---|---|
| `mcp_server.py` | MCP-сервер: регистрирует `search`, `summarize`, `save_to_file` с описанием параметров |
| `tools_impl.py` | логика инструментов (отдельно, чтобы её можно было тестировать) |
| `pipeline.py` | **автоматический пайплайн**: вызывает инструменты по цепочке и проверяет передачу данных |
| `mcp_client.py` | подключение к серверу по stdio, разбор результата |
| `run.ps1` | запуск в одну команду |

## Инструменты

| Инструмент | Роль в цепочке | Параметры | Возвращает |
|---|---|---|---|
| `search` | получает данные | `query`, `top_k` (1–10) | статьи, `combined_text`, его sha256 |
| `summarize` | обрабатывает | `text`, `max_sentences` (1–20), `mode` (`extractive` / `llm`) | выжимку и sha256 **полученного** текста |
| `save_to_file` | сохраняет | `filename`, `content` | путь, размер и sha256 **записанного** файла |

Источник данных — встроенная база статей (MCP, RAG, контекст, function calling),
поэтому пайплайн работает без интернета. Суммаризация по умолчанию локальная
(выбор ключевых предложений); режим `llm` делает выжимку через AITunnel.

## Как проверяется передача данных

| Проверка | Что сравнивается |
|---|---|
| search → клиент | sha256 текста, который пришёл клиенту, и тот, что посчитал сервер |
| клиент → summarize | sha256 текста, который получил summarize, и того, что вернул search |
| выжимка из исходных данных | каждое предложение выжимки есть в найденных статьях (режим `extractive`) |
| summary → отчёт | все предложения выжимки попали в отчёт |
| клиент → save_to_file | sha256 записанного на диск и отправленного |
| файл на диске | файл перечитывается и сверяется с отчётом |

Если любая проверка не прошла или шаг вернул ошибку (ничего не найдено,
неверный ключ и т.п.) — пайплайн останавливается и **ничего не сохраняет**.

## Запуск (PowerShell)

```powershell
cd "путь\до\day19-mcp-pipeline"
Unblock-File .\run.ps1
.\run.ps1                                       # без ключа
.\run.ps1 -Query "RAG и поиск" -Sentences 3     # свой запрос
.\run.ps1 -Llm -Model gpt-5.6-luna              # выжимка через LLM, ключ спросит скрыто
```

Результат — в папке `output/`: отчёт `summary_*.md` и трассировка всех шагов
`pipeline_trace.json`.

## Проверка ТЗ

| Пункт ТЗ | Где |
|---|---|
| Несколько MCP-инструментов: search, summarize, saveToFile | `mcp_server.py` |
| Первый получает данные | шаг 1 — `search` |
| Второй обрабатывает | шаг 2 — `summarize` |
| Третий сохраняет результат | шаг 3 — `save_to_file` |
| Автоматическое выполнение цепочки | `pipeline.py` — одна команда, три шага подряд |
| Корректность передачи данных | 6 проверок на стыках шагов, итог «проверок пройдено: 6/6» |
