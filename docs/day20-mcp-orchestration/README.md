# День 20. Orchestration MCP

Четыре независимых MCP-сервера, общий реестр, маршрутизатор и агент,
который сам выбирает инструменты в длинном многошаговом сценарии.
Корректность выбора и порядка вызовов проверяется автоматически.

## Архитектура

```
                         servers.json (реестр)
                                │
 Пользователь ──► Агент ──► Оркестратор ──┬──► crm    (клиенты, заказы)
                    ▲    каталог + роутинг ├──► kb     (база знаний: search, summarize)
                    │                     ├──► tasks  (задачи)
             LLM или сценарий             └──► files  (отчёты: save_to_file, search)
```

- **Реестр** (`servers.json`) — список серверов. Добавить сервер = добавить строку.
- **Оркестратор** (`orchestrator.py`) — запускает все серверы, собирает единый
  каталог инструментов под именами `сервер__инструмент` и направляет каждый
  вызов на сервер-владелец. Каждый вызов пишется в журнал.
- **Агент** (`agent.py`) — цикл «выбрать инструмент → вызвать → получить результат»
  до финального ответа. Два планировщика:
  - `llm` — модель через AITunnel **сама выбирает** инструменты из общего каталога;
  - `scripted` — эталонный маршрут без модели, для проверки оркестрации без ключа.

### Ловушка для маршрутизации

Инструмент `search` есть на двух серверах: `kb` (база знаний) и `files`
(сохранённые отчёты). В каталоге они различаются как `kb__search` и
`files__search`, а описания подсказывают модели, что где искать.
Сценарий требует в ходе 1 искать в базе знаний, а в ходе 2 — в файлах.

## Сценарий (длинный флоу: 2 хода, 8 вызовов, 4 сервера)

**Ход 1.** «Клиентка Анна Смирнова. Посмотри её заказы, найди в базе знаний
рекомендации по услуге из её последнего заказа и сделай короткую выжимку.
Создай задачу позвонить ей через два дня и сохрани отчёт в файл.»

```
crm.search_clients → crm.get_client_orders → kb.search → kb.summarize
                   → tasks.create_task → files.save_to_file
```

**Ход 2.** «Найди среди сохранённых файлов отчёт по Смирновой и покажи все
открытые задачи.» → `files.search`, `tasks.list_tasks` — второй ход опирается
на то, что было создано в первом.

## Автоматические проверки (16 штук)

| Группа | Что проверяется |
|---|---|
| Маршрутизация | каждый вызов ушёл на сервер-владелец, неизвестных инструментов нет |
| Разные серверы | задействованы все 4 сервера |
| Выбор | в каждом ходе вызваны нужные инструменты; `kb.search` и `files.search` не перепутаны |
| Порядок | 5 зависимостей: клиент раньше заказов, поиск раньше выжимки, выжимка раньше отчёта и т.д. |
| Передача данных | client_id из CRM дошёл до заказов и задачи; выжимка сделана из найденных статей; отчёт содержит клиента |
| Связь ходов | ход 2 находит отчёт и задачу, созданные в ходе 1 |
| Ошибки | ошибка допустима, только если агент исправил её повторным вызовом |

Порядок проверяется через зависимости, а не жёсткую последовательность:
модель может выбрать другой корректный порядок — это не считается ошибкой.

Проверки отдельно протестированы на «плохом агенте»: перепутанный `search`,
нарушенный порядок, чужой client_id, выдуманный текст для выжимки,
несуществующий инструмент, пропущенный шаг — всё это ловится.

## Запуск (PowerShell)

```powershell
cd "путь\до\day20-mcp-orchestration"
Unblock-File .\run.ps1
.\run.ps1 -Mode list                       # реестр и каталог инструментов
.\run.ps1                                  # флоу без LLM
.\run.ps1 -Mode llm -Model gpt-5.6-luna    # флоу, инструменты выбирает модель
```

Результат в `output/`: `orchestration_report.md` (таблица вызовов и проверок),
`orchestration_trace.json` (полный журнал), `client_2_report.md` (отчёт из сценария).

## Проверка ТЗ

| Пункт ТЗ | Где |
|---|---|
| Зарегистрировать несколько MCP-серверов | `servers.json` + `orchestrator.py` (4 сервера) |
| Агент выбирает нужный инструмент | режим `llm`: модель выбирает из общего каталога 12 инструментов |
| Корректно маршрутизирует запросы | `Orchestrator.call`: `сервер__инструмент` → нужная сессия |
| Выполняет длинный флоу | 2 хода, 8 вызовов, 4 сервера |
| Сценарий с инструментами разных серверов | проверка «Инструменты с разных серверов» |
| Корректность выбора и порядка вызовов | проверки «Выбор», «Порядок», «Передача данных» |
