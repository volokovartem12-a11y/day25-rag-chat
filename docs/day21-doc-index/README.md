# День 21. Индексация документов

Локальный индекс документов: chunking → эмбеддинги → SQLite, с метаданными
у каждого чанка и сравнением двух стратегий chunking.

## Корпус

Папка `docs/` — проекты челленджа (дни 9–20): **43 документа** — 10 README/отчётов
и 33 файла кода. **213 тыс. символов ≈ 119 страниц** (1 стр. = 1800 знаков) —
с запасом больше требуемых 20–30.

Поддерживаются `.md`, `.txt`, `.py`, `.pdf` (PDF → текст постранично).
Свои документы можно просто положить в `docs/` и пересобрать индекс.

## Пайплайн

```
docs/ ─► loaders.py ─► chunking.py ─────────► embeddings.py ─► index_store.py
         текст          fixed / structure     local / aitunnel  SQLite + JSON
                        + метаданные
```

| Файл | Роль |
|---|---|
| `loaders.py` | загрузка md / txt / py / pdf → текст, заголовок документа |
| `chunking.py` | две стратегии нарезки + метаданные |
| `embeddings.py` | эмбеддинги: `local` (без сети) и `aitunnel` (семантические) |
| `index_store.py` | сохранение в SQLite, JSON-экспорт, поиск по косинусной близости |
| `build_index.py` | весь пайплайн: собирает индекс для каждой стратегии |
| `compare.py` | сравнение стратегий → `output/chunking_comparison_*.md` |
| `search.py` | поиск по индексу из командной строки |
| `eval_questions.json` | 15 контрольных вопросов с известными ответами |

## Метаданные чанка

`chunk_id` · `strategy` · `source` (путь) · `file` · `title` (заголовок документа) ·
`section` (раздел) · `position` · `char_start` / `char_end` (точные смещения в исходнике).

Пример: `day19-mcp-pipeline/tools_impl.py#structure-009`, раздел `def _safe_filename`.

## Две стратегии chunking

**fixed** — окно 1000 символов с перекрытием 150. Границы сдвигаются к пробелу,
чтобы не резать слова. Раздел в метаданных — тот, где начинается чанк.

**structure** — по структуре документа:
- Markdown — по заголовкам, раздел в виде пути «Глава > Подраздел»; `#` внутри
  блоков кода заголовком не считается;
- Python — по функциям, классам и константам верхнего уровня; декораторы и
  комментарии над ними входят в раздел; методы класса не дробятся;
- PDF — по страницам; текст — по абзацам;
- длинные разделы (> 1500) делятся по абзацам, мелкие (< 200) склеиваются с соседом.

## Эмбеддинги

- **local** — без сети и ключа: хешированный TF-IDF (1024), признаки — основы слов,
  биграммы и части идентификаторов кода (`save_to_file` → save, to, file).
  Это **лексические** векторы: хорошо ловят общие термины, но не синонимы.
- **aitunnel** — **семантические** эмбеддинги `text-embedding-3-small` (1536) через AITunnel.

## Результаты сравнения

Оба прогона выполнены на реальном корпусе (43 документа, ≈ 118.6 стр.) командами
`.\run.ps1` и `.\run.ps1 -Backend aitunnel`. Параметры: fixed — 1000 символов
с перекрытием 150; structure — максимум 1500, минимум 200.

### Качество нарезки (не зависит от эмбеддингов)

| Метрика | fixed | structure |
|---|---|---|
| Чанков | 264 | 285 |
| Размер: средний / мин / макс | 925 / 192 / 999 | 746 / 202 / 1631 |
| Разброс размеров (stdev) | **174** | 392 |
| Начинаются с начала раздела | 16.3% | **86.0%** |
| Обрыв посреди строки | 62.1% | **0.0%** |
| Разорванные блоки кода в Markdown | 28.6% | **0.0%** |
| Метаданные заполнены | 100% | 100% |

### Качество поиска на 15 контрольных вопросах

| Метрика | fixed, local | structure, local | fixed, AITunnel | structure, AITunnel |
|---|---|---|---|---|
| Эмбеддинги | хешированный TF-IDF, 1024 | хешированный TF-IDF, 1024 | text-embedding-3-small, 1536 | text-embedding-3-small, 1536 |
| hit@1 — нужный файл первым | 0.600 | 0.600 | **0.733** | 0.667 |
| hit@3 — нужный файл в топ-3 | 0.867 | 0.933 | 0.867 | **1.000** |
| MRR | 0.711 | 0.733 | 0.789 | **0.811** |
| section@3 — нужный **раздел** в топ-3 | 0.000 | 0.500 | 0.500 | **1.000** |
| Контекст топ-3, символов | 2943 | 2415 | 2880 | **2361** |
| Время построения эмбеддингов | 0.2 с | 0.2 с | 9.4 с | 8.1 с |

### Выводы

- **structure на семантических эмбеддингах нашла нужный файл и нужный раздел
  для всех 15 вопросов** (hit@3 = 1.0, section@3 = 1.0) — лучший результат из четырёх.
- **fixed рвёт смысловые единицы**: 62% чанков обрываются посреди строки, метка
  раздела часто не совпадает с содержимым. На AITunnel fixed полностью упустила
  два вопроса — про описание параметров через `Field` и про перевод инструментов
  в function calling: нужный код разрезан между чанками.
- **Семантика против лексики**: вопрос про чтение SSE-потока локальные векторы не
  нашли ни одной стратегией, а AITunnel нашёл у обеих — модель понимает смысл,
  даже когда слова в вопросе и в коде разные. Локальные эмбеддинги годятся для
  быстрой проверки без сети, для настоящего поиска нужны семантические.
- **Где fixed сильнее**: предсказуемый размер чанков и чуть выше hit@1 на AITunnel
  (0.733 против 0.667) — правильный файл чаще оказывается именно первым. Но structure
  почти всегда держит его в топ-3, причём с правильным разделом.
- **Контекст**: structure на 18% экономнее — меньше лишнего текста уйдёт в модель
  на следующем шаге RAG.

**Итог:** для индекса документации и кода лучше **structure** — чанки совпадают со
смысловыми единицами, метаданные точные, поиск нужного раздела в 2 раза надёжнее.

## Запуск (PowerShell)

```powershell
cd "путь\до\day21-doc-index"
Unblock-File .\run.ps1
.\run.ps1                                     # индексация + сравнение, без ключа
.\run.ps1 -Backend aitunnel                   # с эмбеддингами AITunnel
.\run.ps1 -Mode search -Query "как защититься от записи за пределы output"
```

Результат:
- `index/index_fixed_<backend>.sqlite`, `index/index_structure_<backend>.sqlite` — индексы;
- `index/*.chunks.json` — метаданные всех чанков в читаемом виде;
- `output/chunking_comparison_<backend>.md` — отчёт сравнения.

## Проверка ТЗ

| Пункт ТЗ | Где |
|---|---|

| Минимум 20–30 страниц | ≈ 119 страниц |
| Chunking | `chunking.py` |
| Генерация эмбеддингов | `embeddings.py` (local и aitunnel) |
| Сохранение индекса | SQLite (`index/*.sqlite`) + JSON (`index/*.chunks.json`) |
| Метаданные: source, title/file, section, chunk_id | у каждого чанка, заполнены на 100% |
| 2 стратегии: фиксированный размер и по структуре | `fixed`, `structure` |
| Сравнение стратегий | `compare.py` → `output/chunking_comparison_*.md`; результаты на local и AITunnel — выше |
