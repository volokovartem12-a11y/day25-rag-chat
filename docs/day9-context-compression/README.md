# День 9. Управление контекстом: сжатие истории

Сделано в том же формате, что и `day7-context-memory`: агент на Python,
ключ берётся из переменной окружения, запуск через PowerShell.

## Файлы

- `context_manager.py` — переиспользуемый класс `ContextManager`:
  хранит последние `keep_last_n` сообщений «как есть», а более старые
  каждые `summarize_every` сообщений сворачивает в summary отдельным
  вызовом LLM. Summary хранится отдельно и дополняется, а не
  перезаписывается, при каждой новой свёртке.
- `chat.py` — **интерактивный агент** с компрессией истории (это и есть
  результат задания — "агент, который работает с компрессией истории и
  экономит токены"). Работает через AITunnel.
- `compare.py` — **скрипт сравнения**: прогоняет один и тот же сценарий
  диалога (20 реплик про планирование поездки, с деталями, которые
  спрашивают повторно — бюджет, аллергия) дважды через реальный API:
  без сжатия и со сжатием, — и сравнивает реальный расход токенов
  (`usage.prompt_tokens` из ответов API), сохраняя оба транскрипта в
  JSON для ручного сравнения качества.

## Установка (один раз)

```powershell
pip install openai
```

## Запуск — интерактивный агент

```powershell
cd "путь\до\day9-context-compression"
$env:AITUNNEL_API_KEY = "sk-aitunnel-xxx"
python .\chat.py
```

Внутри чата:
- `/stats` — расход токенов (реальный, со сжатием) и оценка того, сколько
  токенов ушло бы без сжатия;
- `/summary` — показать текущее накопленное summary;
- `/exit` — выход.

Необязательные переменные окружения (значения по умолчанию — в скобках):

```powershell
$env:AITUNNEL_MODEL = "gpt-4o-mini"          # (gpt-4o-mini) любая модель из каталога AITunnel
$env:AITUNNEL_SUMMARY_MODEL = "gpt-4o-mini"  # (= AITUNNEL_MODEL) можно взять модель подешевле для сжатия
$env:KEEP_LAST_N = "6"                       # (6) сколько последних сообщений хранить как есть
$env:SUMMARIZE_EVERY = "10"                  # (10) раз в сколько сообщений сжимать
```

## Запуск — сравнение до/после

```powershell
cd "путь\до\day9-context-compression"
$env:AITUNNEL_API_KEY = "sk-aitunnel-xxx"
python .\compare.py
```

⚠️ Скрипт делает реальные запросы к API на обоих прогонах (без сжатия и со
сжатием) — тратит токены дважды. Сценарий уже укорочен до 20 реплик, чтобы
ограничить стоимость; при желании отредактируйте `SIMULATED_TURNS` в
`compare.py`.

Без ключа (`AITUNNEL_API_KEY` не задан) оба скрипта либо не запустятся
(`chat.py` требует ключ), либо `compare.py` уйдёт в MOCK-режим — без
реальных вызовов, только чтобы проверить механику и увидеть структуру
сравнения.

## Результаты (пример прогона в MOCK-режиме, 20 реплик)

| Метрика | Без сжатия | Со сжатием |
|---|---|---|
| input-токены | 7124 | 5857 |
| Экономия | — | **1267 ток. (17.8%)** |
| Вызовов суммаризации | 0 | 6 |

Экономия в MOCK-режиме ниже, чем в предыдущем офлайн-прогоне на 40 репликах
(там было ~56%), потому что здесь сценарий короче (20 реплик) и
`keep_last_n=4` / `summarize_every=6` — окно сжатия срабатывает чаще, но
на коротком диалоге разница ещё не успевает "накопиться" так сильно, как на
длинном. На реальном API с более длинными диалогами экономия растёт вместе
с длиной истории: без сжатия каждый следующий запрос тащит за собой **всю**
историю, а со сжатием размер запроса после первой свёртки стабилизируется.

## Как оценить качество (реальный прогон)

1. Запустите `compare.py` с реальным `AITUNNEL_API_KEY`.
2. Откройте `transcript_no_compression.json` и `transcript_with_compression.json`.
3. Проверьте ответы на "контрольные" вопросы сценария (специально
   разнесены с фактами, которые они проверяют):
   - "Напомни, какой у нас бюджет на человека?"
   - "Помнишь про аллергию на арахис?"
   - "Напомни про морепродукты — я вроде говорил, что не ем."
   - "Напомни весь бюджет — сколько всего на двоих получается?"
4. Если в версии со сжатием деталь потерялась — увеличьте `KEEP_LAST_N`
   или усильте промпт суммаризации в `default_summarizer_factory`
   (`context_manager.py`).

Компромисс стандартный: меньше `SUMMARIZE_EVERY` / больше `KEEP_LAST_N` →
выше качество, меньше экономия токенов; и наоборот.
