Прогнано на реальном API AITunnel — раздел 3 (качество) заполните сами после
сверки `transcript_no_compression.json` и `transcript_with_compression.json`.

| Параметр | Значение |
|---|---|
| Модель (ответы) | `AITUNNEL_MODEL` = gpt-4o-mini (по умолчанию) |
| Модель (суммаризация) | `AITUNNEL_SUMMARY_MODEL` = gpt-4o-mini (по умолчанию) |
| `KEEP_LAST_N` | 4 (значение по умолчанию в compare.py) |
| `SUMMARIZE_EVERY` | 6 (значение по умолчанию в compare.py) |

| Дата прогона | 11.09.2026 |

## 2. Расход токенов (реальные `usage.prompt_tokens` из API)

| Метрика | Без сжатия | Со сжатием |
|---|---|---|
| input-токены (сумма за диалог) | 80118 | 34694 |
| output-токены (сумма за диалог) | 7982 | 7908 |
| Экономия input | — | 45424 ток. (56.7%) |
| Вызовов LLM на суммаризацию | 0 | 6 |

**Вывод:** сжатие истории дало экономию input-токенов 56.7% на 20-репличном сценарии, при этом output практически не изменился (7982 vs 7908) — это ожидаемо, так как сжимается контекст на входе, а не длина самих ответов.
